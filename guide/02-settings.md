# 끄기·설정 목록 (Jira·Confluence·Synology Chat)

**왜 끄나요?** 연구에서 가장 흔한 Jira+Slack 운용은 도구 운용 중 **최하위권**이었습니다(첫 관리직 기준 관리자 점수 39.5, 추천 방식 68.0). 메신저가 달라도 원리는 같습니다. 개인 지표와 상시 알림이 문제입니다. 주간 체크인 의무·리뷰-보상 연계·전원 성장 플랜 의무를 켠 현실형 묶음은 관리 바닥보다 10.6점 낮았습니다. **시뮬레이션 기반 가설입니다.** 실제 조직에서 잰 값이 아닙니다.

한 줄로: **사람을 세는 화면은 끄고, 일과 막힘이 보이는 화면만 켭니다.**

## 0. 순서 (15분, 처음이면 30분까지)

- 메뉴 이름은 영어 화면 기준입니다. 한국어 화면에서는 다를 수 있습니다(확인 필요).
- Jira Cloud는 '이슈'를 '작업 항목(work item)', '프로젝트'를 '스페이스(space)'로 바꿔 부르기도 합니다. 같은 것입니다.

## 1. Jira

**먼저 내 종류를 고릅니다.** 아래 경로는 ①을 기준으로 씁니다.
- 주소가 `○○.atlassian.net`이면 Cloud입니다. 아니면 Data Center입니다.
- Cloud면 프로젝트 사이드바 맨 아래에 '회사 관리형(company-managed)'인지 '팀 관리형(team-managed)'인지 적혀 있습니다(확인 필요).
- 내 종류: ☐ ① Cloud 회사 관리형 ☐ ② Cloud 팀 관리형 ☐ ③ Data Center

### 1-1. 끌 것

**① 담당자별 스윔레인**
- 무엇을: 보드 줄을 '담당자'로 나눴다면 '에픽' 또는 '없음'으로.
- 어디서: 보드 → 더보기(•••) → Board settings → Swimlanes → Epics 또는 No swimlanes.
- 다른 종류면: ② 보드 위 **Group by**를 담당자가 아닌 것으로(확인 필요). ③ Board → Configure → Swimlanes(확인 필요).
- 권한: 보드 관리자. 아니면 '부탁 문장 A'.

**② 사람 이름이 붙은 빠른 필터**
- 무엇을: '○○ 담당' 같은 사람별 빠른 필터를 지웁니다. 각자 자기 일만 보는 'Only My Issues'는 둬도 됩니다.
- 어디서: Board settings → Quick Filters.
- 다른 종류면: ② 사람별 빠른 필터를 따로 만들 수 없습니다(확인 필요). 보드 위 담당자 사진 필터는 팀장이 쓰지 않습니다. ③ Configure → Quick Filters(확인 필요).
- 권한: 보드 관리자.

**③ 사람별 업무량 화면·개인 대시보드**
- 무엇을: 내 대시보드에서 담당자 기준 가젯을 뺍니다. 예: 담당자 기준 Workload Pie Chart, 담당자 통계(가젯 이름은 확인 필요).
- 'User Workload Report'(Data Center 보고서)도 쓰지 않습니다. 팀원별 대시보드를 새로 만들지 않습니다.
- 어디서: Dashboards → 내 대시보드 → 가젯 오른쪽 위 메뉴 → 삭제(확인 필요).
- 권한: 내가 만든 것은 됩니다. 남이 만들어 공유한 것은 만든 사람에게 부탁합니다.

**④ 타임트래킹(작업 시간 기록)**
- 무엇을: 팀에서 시간 기록을 쓰지 않습니다. 할 수 있으면 우리 프로젝트에서 칸을 숨깁니다.
- 어디서: 화면·필드 설정이라 **Jira 관리자 일**입니다 → '부탁 문장 B'.
- 다른 종류면: ② Space settings → 작업 유형(Work types) → 각 유형에서 Time tracking 칸 빼기(확인 필요, 스페이스 관리자).
- 칸을 못 숨겨도 됩니다. **"우리 팀은 시간 기록을 하지 않는다"고 헌장에 쓰는 것**이 먼저입니다(헌장 3절에 있음).
- 회사가 시간 기록을 정산 등에 의무로 쓰면 그 목적에만 씁니다. 4절 확인을 봅니다.

**⑤ 스토리 포인트의 평가 연동**
- 무엇을: 포인트는 팀이 일 크기를 가늠할 때만 씁니다. 사람별로 더하지 않고, 평가 자료에 넣지 않습니다.
- 권한: 설정이 아니라 약속입니다.

**⑥ 개인 번다운·개인 속도 차트**
- 무엇을: 담당자 필터로 번다운·속도 차트를 만들지 않습니다. 기본 번다운은 스프린트(팀) 단위입니다. 이것만 씁니다(확인 필요).
- 스프린트 보고서의 '못 끝낸 항목'을 사람별로 세지 않습니다.
- 권한: 약속입니다.

**⑦ 카드의 '열에 머문 날' 점 (Days in column)**
- 무엇을: 카드마다 한 열에 머문 날 수를 점으로 보여 주는 표시를 끕니다. 카드별 경고 신호라서 끕니다.
- 어디서: Board settings → Card layout(또는 Layout → Card layout) → **Days in column** 끄기.
- 칸반 보드는 기본으로 켜져 있고, 스크럼 보드는 기본으로 꺼져 있습니다.
- 다른 종류면: ② 이 표시가 없을 수 있습니다(확인 필요). ③ Configure → Card layout(확인 필요).
- 권한: 보드 관리자.

### 1-2. 켤 것

**① 동시 착수 2개 (약속으로 켬, Jira 열 상한은 기본 걸지 않음)**
- 약속은 '한 사람 2개, 각자 지킴'입니다. Jira 기본 기능은 사람별 상한을 못 겁니다. 열 단위만 됩니다.
- 그래서 Jira에는 **걸지 않습니다**('틀' 문서와 같음). 열이 빨개지면 누가 넘었는지 카드를 훑게 되기 때문입니다.
- 팀장이 담당자 필터로 세지 않습니다. 사람별 상한 앱도 깔지 않습니다.
- 팀이 원하면 4주 회고에서 정해 켭니다. 그때 경로: Board settings → Columns → Column constraint → Issue count → '진행 중' 열 Max(확인 필요). 숫자는 팀장 포함 실무 인원 × 2.

**② 막힘은 Chat 채널이 기본, Jira 플래그는 선택**
- 막힘·헷갈림은 Chat **`#막힘-헷갈림`** 채널에 올리는 것이 기본입니다(헌장 2절).
  - 채널 이름은 가칭입니다. 10-26 팀 약속에서 이름을 확정합니다.
  - 채널은 팀장이 0주에 가칭으로 만듭니다(시작 준비 0주 체크리스트).
  - 한글 이름이 안 되면 `#help-blocked`를 씁니다.
- 팀장은 이 채널 알림을 **'전체(All)'**로 둡니다. 그래야 글이 올라오면 바로 압니다(3절 ②).
- 팀장이 없을 때
  - 당번 2인 순번이 정해진 뒤에는 당번이 받습니다.
  - 당번이 정해지기 전에는, 부재 중에 온 글을 **복귀일 09시부터 셉니다**. 부재 공지에 복귀일을 적습니다.
  - 이 도구에서는 부재 기간을 설정 탭의 '쉬는 날'에 넣습니다.
- Jira 플래그는 카드를 노랗게 보이게 하고 싶을 때만 덧붙입니다. 헷갈림에는 플래그를 걸지 않습니다('틀' 문서와 같음).
  - 어디서: 보드나 백로그의 카드 → 더보기(•••) → Add flag → 뜨는 창에 코멘트 한 줄.
  - 다른 종류면: ③ 카드 우클릭 → Add flag(버전에 따라 Add flag and comment, 확인 필요).
- 플래그만 걸면 팀장에게 알림이 가는지 알 수 없습니다(확인 필요). 그래서 플래그를 쓸 때도 **채널에 한 줄을 같이** 올립니다. 채널에 못 올리면 플래그 코멘트에 `막힘: … @팀장`처럼 멘션합니다(멘션 알림이 가는지 확인 필요).
- 저장 필터(선택): `Flagged = Impediment`. 월요일 막힘 풀기 때 **남은 막힘을 모아 보는 용도**입니다. 채널 글을 대신하지 않습니다. 매일 열지 않고, 메일 구독도 걸지 않습니다.
- 권한: 플래그는 보통 항목 편집 권한이면 됩니다. 안 보이면 '부탁 문장 A'(확인 필요).

**③ 사이클 = 스프린트 6주**
- 스크럼 보드: 스프린트 시작(Start sprint) 창 → Duration → **Custom** → 끝 날짜를 6주 뒤 금요일로. 정리 주(쿨다운) 1주는 스프린트를 열지 않습니다.
- 칸반 보드: 따로 만들 것이 없습니다. 진행 지도에 사이클 이름만 둡니다('틀' 문서와 같음). 진행 지도가 생기기 전(5주 차 전)에는 사이클 이름을 보드 이름이나 결정 로그에 적습니다. 버전(Releases)은 선택입니다. ②는 기능 켜기에서 Releases를 켜야 할 수 있습니다(확인 필요).
- 일이 작은 팀은 4주 + 1주도 됩니다.
- 권한: 스프린트 시작·완료는 'Manage sprints' 권한. 없으면 '부탁 문장 A'.

**④ 못 끝낸 일은 그대로 이월**
- 스프린트 완료(Complete sprint) 창에서 남은 항목을 옮길 곳을 고릅니다(백로그, 기존 다음 스프린트, 새 스프린트). 완전 자동은 아니고 이 창에서 한 번 고릅니다.
- '지연'·'이월' 라벨, 빨간색, 사유서는 붙이지 않습니다. 이월 항목에 `범위 줄이기 결정:` 코멘트 한 줄만 남깁니다('틀' 문서 6절과 같음).
- 부모 항목은 완료 열에 있는데 하위 작업이 남아 있으면 스프린트가 안 닫힐 수 있습니다(확인 필요). 그때는 **부모를 진행 중으로 되돌려** 같이 이월합니다. **끝나지 않은 일을 완료로 표시하지 않습니다.**

### 1-3. Jira 관리자에게 부탁할 문장

**부탁 문장 A (보드·스프린트 권한)**
> 안녕하세요. ○○팀 팀장 ○○○입니다. 저희 팀 보드 설정(스윔레인, 카드 표시)과 스프린트 시작·완료를 제가 직접 하려고 합니다. 저를 이 보드의 관리자로 넣어 주시고, 저희 프로젝트의 'Manage sprints' 권한을 주실 수 있을까요? 다른 팀 설정은 건드리지 않습니다.

**부탁 문장 B (시간 기록 칸 숨기기)**
> 저희 팀은 작업 시간 기록을 쓰지 않기로 했습니다. 사이트 전체는 그대로 두고, ○○ 프로젝트 화면에서만 Time tracking 칸을 숨겨 주실 수 있을까요? 어렵다면 그대로 두셔도 됩니다. 팀 안에서 쓰지 않는 것으로 정하겠습니다.

## 2. Confluence

### 2-1. 켤 것

**① 팀 공간 페이지 트리 (한 번에 다 만들지 않음)**
```
팀 홈
├─ 팀 약속(헌장)   ← 0주
├─ 결정 로그       ← 1주(헌장 합의 뒤)
└─ 진행 지도       ← 5주 차(11-23 주), 사이클마다 한 장
```
- 0주(이 목록 15분)에는 **팀 홈과 팀 약속(헌장) 페이지만** 만듭니다.
- 결정 로그는 1주에 헌장 합의 뒤 만듭니다. 진행 지도는 5주 차(11-23 주)에 만듭니다.
- 피치·완료 정의·Jira 규칙(1주)과 사이클 회고(정리 주)를 거는 순서는 '틀' 문서 도입 순서를 따릅니다.
- 표 모양은 '틀' 문서에 있습니다. 붙여 넣기만 합니다.
- 결정 로그 칸 구성은 '틀' 문서 1절을 따릅니다. 사람 평가 칸은 두지 않습니다.
- 결정(Decision) 기본 템플릿이 있을 수 있습니다. 이름과 위치는 확인 필요. 없어도 표 하나면 됩니다.
- 어디서: 팀 공간 → 페이지 만들기(+) → 부모 페이지 아래로 끌어 놓기.
- 권한: 그 공간에 쓰기 권한이면 됩니다.

**② 페이지 감시(Watch)는 본인 선택**
- 팀원에게 "진행 지도·결정 로그를 감시하세요"라고 요구하지 않습니다. 보고 싶은 사람만 페이지 오른쪽 위에서 Watch를 누릅니다.
- 다른 사람을 감시자로 대신 넣는 기능이 있더라도 쓰지 않습니다(그런 기능이 있는지 확인 필요).
- 팀장은 결정 로그 하나만 감시합니다. 알림 메일이 많으면 끕니다.
- 권한: 개인 설정.

### 2-2. 끌 것

**③ 페이지 조회 분석을 사람 평가에 쓰지 않기**
- '누가 몇 번 봤는지'로 사람을 보지 않습니다. 결정 로그를 안 읽은 사람을 찾지 않습니다.
- 더 할 수 있으면(Cloud): Confluence 관리자가 Settings → Security → Security configuration → **Hide personal data in analytics**를 켜면 분석 화면에서 이름이 가려집니다. 사이트 전체 설정이라 부탁만 해 봅니다.
- 더 할 수 있으면(Data Center): 공간 관리자가 Space tools → Permissions → Analytics Permissions에서 분석 보기를 제한할 수 있습니다(확인 필요: 회사 버전).
- 권한: Cloud는 Confluence 관리자. Data Center 공간 단위는 공간 관리자.

**Confluence 관리자에게 부탁할 문장 (선택)**
> 저희 팀은 페이지 조회 기록을 사람 평가에 쓰지 않기로 했습니다. 혹시 사이트에 'Hide personal data in analytics'를 켜실 계획이 있으면 알려 주세요. 어렵다면 그대로 두셔도 됩니다.

## 3. Synology Chat

아래는 Synology 공식 도움말·사양(DSM 7 기준)입니다. 우리 회사 버전에 있는지는 확인 필요입니다.

| 기능 | 있나 | 어떻게 쓰나 |
|---|---|---|
| 알림 끄기 일정 | 있음 | 19\~08시 매일 |
| 채널별 알림 | 있음 | `#막힘-헷갈림`만 '전체' |
| 예약 발송 | 있음 | 밤 메시지는 다음 근무일 09:30에 |
| 리마인더 | 있음 | 선택. 이 도구의 막힘 탭에 덧붙여 씀 |
| 봇·웹훅 | 있음 | **쓰지 않음** |
| 전체 멘션(@all 등) | 못 찾음(확인 필요) | 있으면 쓰지 않음 |
| 접속 상태 숨기기 | 못 찾음(확인 필요) | 못 끄면 보지 않음 |
| 읽음 표시 | 못 찾음(확인 필요) | 있어도 보지 않음 |

**① 근무시간 외 알림 끄기**
- Chat: 알림 끄기(Mute notifications) 아이콘 → Snooze schedule → Settings → Enable snooze schedule → 시작 19:00, 끝 08:00. 매일 반복, 웹·휴대폰 모두 적용.
- 주말: Chat 일정에는 요일 고르기가 도움말에 없습니다. 그래서 **휴대폰 방해 금지(집중 모드) 일정에 토·일 종일을 한 번** 걸어 둡니다. 메뉴 이름은 휴대폰 기종마다 다릅니다(확인 필요).
- 휴대폰 일정을 못 쓰는 날만 Chat의 Mute notifications → **Mute for**를 임시로 씁니다(고를 수 있는 길이는 확인 필요).
- 시간대: 프로필 → Settings → Profile → Time zone이 서울인지 봅니다.
- 팀원에게는 **권하기만** 합니다. 켰는지 확인하지 않습니다.
- 권한: 본인 설정.

**② 막힘 채널 알림 '전체'**
- Chat은 대화·채널마다 알림을 '전체 / 멘션·구독 스레드 / 멘션만 / 없음' 중에서 고를 수 있습니다.
- `#막힘-헷갈림` 채널만 **전체**로 둡니다. 다른 채널은 '멘션만'이어도 됩니다. 메뉴 위치는 채널 이름 옆 설정(확인 필요).
- 위 알림 끄기 일정이 켜져 있으니 밤·주말에는 울리지 않습니다.
- 권한: 본인 설정.

**③ 예약 발송 (Scheduled message)**
- 어디서(웹): 입력창 아래 **Schedule a message** 아이콘 → 날짜·시간 → 내용. 휴대폰은 입력창의 예약 아이콘.
- 주의: 기본값이 **다음 날 정오**입니다. 다음 근무일 09:30으로 바꿉니다. 금요일 밤이면 월요일로.
- 보낼 예정 목록: 오른쪽 위 My Collections → Scheduled messages. 여기서 고치거나 지웁니다.
- 시험은 팀 채널이 아니라 **나에게** 보내 봅니다(나만 있는 대화가 있는지는 확인 필요). 없으면 시험하지 않고, 처음 실제로 쓸 때 위 목록에서 시간만 확인합니다.
- 권한: 본인.

**④ 리마인더 (Remind me)**
- 어디서: 메시지 → 더보기 → **Remind me** → 시간 선택. 휴대폰은 메시지를 길게 누릅니다.
- 기본 도구: 기한 약속을 지키는 기본 도구는 이 도구의 **'막힘' 탭**입니다. 바로 답할 수 없는 글은 여기에 붙여 넣습니다.
- Remind me는 **덧붙여 쓰는 선택 알림**입니다. 쓰고 싶을 때만 겁니다.
  - **막힘**: **다음 근무일 오전 9시대**(금요일이면 월요일)로 겁니다.
  - **헷갈림**: 근무일 1일 안이라서 그날 오후나 다음 근무일 오전으로 겁니다.
- 기한 세는 법
  - 막힘은 근무일 2일, 헷갈림은 근무일 1일입니다.
  - 토·일·공휴일은 세지 않습니다.
  - 19시 이후나 쉬는 날에 들어온 글은 다음 근무일 09시부터, 근무일 08시 이전에 들어온 글은 그날 09시부터 셉니다.
  - 예: 금 17시 막힘 → 화 17시까지. 목 11시 헷갈림 → 금 11시까지.
- 리마인더는 나만 봅니다. 목록은 My Collections에서 봅니다. 알림이 오는 곳은 확인 필요.
- 권한: 본인.

**⑤ 봇·웹훅·슬래시 명령 (Integration)**
- 있습니다. 프로필 사진 → Integration에서 웹훅·봇·슬래시 명령을 만듭니다.
- **쓰지 않습니다.** 스탠드업 봇, 자동 체크인, "오늘 뭐 했나요" 알림은 연구가 끄라고 한 것입니다.
- 일반 사용자가 만들 수 있는지, 관리자가 막아 두었는지는 확인 필요.

**⑥ 전체 멘션·접속 상태·읽음 표시**
- 전체 멘션(@all, @channel 같은 것): 공식 사양에서 찾지 못했습니다(확인 필요). 있으면 쓰지 않고, 끌 수 있으면 끕니다.
- 접속 상태(활동·자리 비움)와 입력 중 표시: 숨기는 설정을 찾지 못했습니다(확인 필요). 끌 수 있으면 끄고, 못 끄면 보지 않습니다. 근무 확인에 쓰지 않습니다.
- 읽음 표시: '누가 읽었는지' 보여 주는 기능을 찾지 못했습니다(확인 필요). 있다면 보지 않습니다. 답이 없다고 다시 재촉하지 않습니다.

**⑦ 관리 콘솔의 메시지 조회 (팀장이 요청하지 않음)**
- Chat 관리자는 관리 콘솔의 Lookup에서 메시지를 검색할 수 있고, 활동 기록(Operation log)도 남습니다.
- 팀장은 팀원 메시지나 활동 기록을 **요청하지 않습니다.**

**예약 발송이 안 되는 버전이라면**
- 밤에 떠오른 지시는 보내지 않습니다.
- 이 도구의 **'적기' 탭 → '나중에 보낼 것'**에 한 줄 적습니다.
- 다음 근무일 아침에 열어서 보냅니다. 아침에 다시 보면 절반은 안 보내도 되는 일입니다.

## 4. 팀장이 보지 않는 것 (팀에 공개할 3줄)

헌장 3절 '팀장이 보지 않는 것, 하지 않는 것'에 이미 같은 뜻의 문장이 있습니다. **새로 붙이지 말고**, 헌장 3절에 아래 내용이 다 들어 있는지만 봅니다. 빠진 것만 헌장 표현에 맞춰 더합니다. 두 곳이 다르면 헌장을 기준으로 합니다.

> 1. 저는 사람별 숫자를 만들지 않고, 사람 평가에 쓰지 않습니다. 사람별 처리 건수, 스토리 포인트 합계, 작업 시간 기록, Confluence 조회 기록이 그것입니다.
> 2. 저는 Chat의 접속·읽음 표시, 답장 속도, 근무시간 밖 답장 여부로 사람을 판단하지 않습니다. Chat을 관리하는 IT 담당자에게 팀원의 메시지나 활동 기록을 요청하지 않습니다.
> 3. 막힘은 `#막힘-헷갈림` 채널로 늘 받습니다. 진행은 Jira 보드의 일감 단위와 Confluence 팀 페이지로 봅니다. 위로 가는 보고에는 개인 이름과 개인 수치를 넣지 않습니다.

**공개하기 전 확인 (0주 HR 문의 때)**
- 회사가 Jira 시간 기록이나 Jira 수치를 평가·정산에 **의무로** 쓰는지 HR에 물어봅니다.
- 정산에만 의무라면 1번에 "회사가 요구하는 기록은 그 목적에만 씁니다"를 붙입니다.
- 평가에 의무라면 1번에서 그 항목을 빼고, 헌장 3절의 '회사 제도로 꼭 해야 하는 일' 문장으로 대신합니다. **지킬 수 없는 약속은 공개하지 않습니다.**
