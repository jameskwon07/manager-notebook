# 양식과 문장

[조심할 것](#guide/watch)의 예방 장치를 한곳에 모았습니다. 대괄호 `[ ]` 안을 채워 씁니다. 수첩 화면에도 같은 것이 있습니다: 회신 문장은 [접수함](#intake), 결정 경계·긴급 기준·서브 최소 의무는 [결정 경계](#bounds), 주간 보고 초안은 [금요일](#friday).

## 1. 접수 양식 7칸

요청자에게는 앞 5칸(원문·무엇·왜·언제까지·확인 방법)만 받습니다. 나머지는 관리자가 채웁니다. 비어 있는 칸만 되묻습니다.

| 칸 | 무엇을 적나 | 비면 |
|---|---|---|
| 원문 | 메신저나 말로 온 요청 그대로(이름은 빼고) | 적을 때 필수 |
| 무엇 | 요청을 한 줄로 | 적을 때 필수 |
| 왜·누가 결정 | 이 일이 왜 필요하고 누가 정했는지 | 되묻기 |
| 어느 프로그램 | 넘길 프로그램(모르면 미정) | 되묻기 |
| 언제까지와 이유 | 날짜와 그 날짜인 이유 | 되묻기 |
| 확인 방법 | 무엇을 보면 끝났다고 할지. 리드의 완료 기준에 그대로 들어갑니다 | 되묻기 |
| 긴급 | 긴급 기준에 맞는지. 맞으면 리드가 바로 처리하고 사후 등록 | 아니요 |

되묻기 문장(접수함의 '되묻기 문장 복사'가 빈칸만 골라 만듭니다):

```
"[요청]" 접수했습니다. 리드에게 넘기기 전에 [n]가지만 여쭙니다.
(1) 왜 필요하고 누가 정했는지 (2) 언제까지, 그 날짜인 이유 (3) 무엇을 보면 됐다고 할지
답 주시면 담당 리드 추정 뒤 근무일 2일 안에 회신드립니다.
```

## 2. 크기 S/M/L

| 크기 | 기준 | 처리 |
|---|---|---|
| S | 반나절 이하 | 10분 안에 정리해 바로 리드에게 넘깁니다. 리드가 직접 받은 S는 사후 등록 |
| M | 1~5일 | 빈칸을 되묻고, 리드 추정(최소·보통·최대)을 받은 뒤 회신 |
| L | 한 사이클을 쓰는 일 | 사이클 계획에서 넣을지 정합니다. 넣으면 무엇이 밀리는지 요청자에게 교환 제안 |

## 3. 결정 경계 1쪽

행마다 최종 결정자는 하나입니다. 팀과 합의한 대로 [결정 경계](#bounds)에서 고칩니다. 단계별로 풀어 쓴 표는 [역할과 책임](#guide/raci)에 있습니다.

| 영역 | 최종 결정 | 비고 |
|---|---|---|
| 파트 전체 구조·통합 설계 | 관리자 | 관리자의 실무 몫. 팀장이 정하기로 한 통합 방향은 팀장 결정, 관리자가 선택지 2~3개를 올림 |
| 다른 파트·다른 프로그램에 걸친 인터페이스 | 관리자 | 리드가 설계안, 상대 프로그램의 리드가 의견, 관리자가 조정·기록 |
| 프로그램 내부 구조·기술 선택·작업 배분·추정 | 그 프로그램의 리드 | 주니어가 리드인 프로그램은 지침 '제약' 칸이 위임 경계 |
| 모듈 설계(위임 범위 안) | 위임받은 사람(승인: 그 프로그램의 리드) | 통째로 다시 하지 않음. 주니어에게는 관리자가 멘토 리뷰 30분 |
| 내부 설계(클래스·함수·자료구조) | 개발자 | 리드는 코딩 규칙만 |
| 코드 병합 | 그 프로그램의 리드 | 리뷰 의무, 리뷰 없는 병합 없음. 서브의 반대는 의견, 리드가 이유와 함께 답하고 기록 |
| 리드·서브 배정, 활성/대기 | 관리자 | 파트 사이 이동·역할 변경은 팀장 |
| 대외 약속·범위 축소·교환 제안 | 2주 이내는 관리자 | 거절과 2주 초과는 팀장 결재 뒤 관리자가 회신 |
| 장애 | 1차 그 프로그램의 리드(기술 판단), 2차 서브 | 관리자는 대외 소통·인력 조정. 야간 대응·배포 결재는 팀에서 정함 |
| 관리자가 리드의 결정을 뒤집는 조건 | 관리자(비고의 네 경우만) | 요구사항 위반 · 큰 일정 영향 · 다른 파트 영향 · 안전·품질. 공개 자리가 아니라 1:1에서 |

**긴급 기준(관리자를 거치지 않음)**

- 운영 중인 장비나 시스템이 멈추거나 데이터가 손실될 때
- 시험·계약 일정에 직접 걸린 결함
- 안전과 관련된 것

기술 판단은 그 프로그램의 리드가 합니다. 처리 뒤 접수함에 사후 등록합니다.

## 4. 서브 최소 의무 한 줄

```
서브 최소 의무: 리뷰 · 회귀 테스트 · 장애 2차 · 분기 1회 혼자 배포.
구현 분담 범위는 사이클 시작 때 리드가 적은 만큼입니다.
```

## 5. 장애 1차·2차

| 단계 | 누가 | 하는 일 |
|---|---|---|
| 긴급인지 판단 | 그 프로그램의 리드 | 긴급 기준에 맞으면 관리자를 거치지 않고 바로 처리 |
| 1차 | 그 프로그램의 리드 | 기술 판단, 분석·수정 지휘 |
| 2차 | 그 프로그램의 서브 | 리드가 없거나 손이 모자랄 때 대응(가정) |
| 대외 소통·인력 조정 | 관리자 | 요청자·다른 파트에 알림, 사람 재배치, 외부 공지 발송(기술 내용은 리드가 씀) |
| 리드·서브가 같은 날 없을 때 | 당번 1인 | 미리 알린 당번이 받음 |
| 끝난 뒤 | 그 프로그램의 리드 | 접수함에 사후 등록, 비난 없는 회고 세 질문 |
| 팀에서 정할 것 | 팀 | 야간 대응 여부, 배포에 회사 결재가 필요한지 |

비난 없는 회고 세 질문:

```
① 무슨 일이 있었나요?
② 그때 무엇이 그렇게 하게 만들었나요(정보·시간·도구)?
③ 다음에 같은 일이 안 생기려면 팀 절차에서 무엇을 바꾸면 될까요?
```

## 6. 회신 문장 6개

**확인 후 회신**

```
[요청] 잘 받았습니다. 날짜는 담당 리드가 추정한 뒤 회신드리겠습니다. 근무일 2일 안에 알려 드립니다.
```

**2주 이내 약속(관리자 재량)**

```
[요청]은 [날짜]까지 가능합니다. 범위는 [최소 범위]로 잡았고, 확인은 [확인 방법]으로 하겠습니다.
```

**교환 제안**

```
[요청]을 이번 사이클에 넣으면 [기존 일]이 [기간] 밀립니다. 어느 쪽을 먼저 할지 [날짜]까지 정해 주시면 그대로 진행하겠습니다.
```

**거절·2주 초과: 팀장에게 올리는 한 줄**

```
요청: [무엇 · 요청자 역할] / 리드 추정: 최소 [ ]일 · 보통 [ ]일 · 최대 [ ]일 / 넣으면 밀리는 것: [ ] / 제안: [축소 · 연기 · 거절 중 하나]
```

**리드에게 넘길 때 세 칸**

```
결정된 것: [ ] / 열린 것: [ ] / 요청자: [역할 · 연락 경로]  (다른 프로그램에 걸치면 그쪽 리드도 참조)
```

**흡수 금지 한 줄**

```
직접 처리하지 않습니다. 접수함에 적고 그 프로그램의 리드에게 넘깁니다. 넘길 자리가 없으면 거절·2주 초과 한 줄로 팀장에게 올립니다.
```

## 7. 주간 서면 보고 틀

[금요일](#friday)의 초안이 이 모양으로 만들어집니다. 진행 지도 두 칸과 접수 현황만 씁니다. 리드가 따로 보고서를 쓰지 않습니다.

```
파트 주간 보고 ([날짜])

1. 위험(진행 지도 위험 칸)
- [항목] ([프로그램]): [위험]

2. 결정 필요
- [항목] ([프로그램]): [무엇을, 누가(역할)]

3. 접수 현황
- 접수 대기 [n]건, 전달 2일 초과 [n]건, 활성 프로그램 [n]개

4. 흡수 건수
- 이번 주 [n]건

개인별 진행률·업무량은 적지 않습니다.
```

격주 팀장 1:1에는 여기에 '2주 초과 약속·거절 결재 요청, 교환 제안 결과'만 더합니다.

## 8. 지침 네 칸(사이클 시작 때, 활성 프로그램마다)

'어떻게'는 쓰지 않습니다. 주니어가 리드인 프로그램은 '제약' 칸이 위임 경계입니다.

| 칸 | 적는 것 |
|---|---|
| 문제 | 이번 사이클에 푸는 문제 한두 줄 |
| 성공 기준 | 무엇을 보면 됐다고 할지 |
| 제약 | 지켜야 할 경계: 인터페이스, 다른 파트, 시간 예산 |
| 빼는 것 | 이번에는 하지 않는 것 |

## 9. 결정 로그 한 줄

```
[날짜] | [결정] | 이유: [ ] | 결정자: [파트 리드 / 프로그램 리드 / 팀장] | [프로그램]
```

결정자는 이름이 아니라 역할로 적습니다. 결정이 바뀌면 줄을 지우지 않고 새 줄을 씁니다.

## 10. 팀 밖 공지 1쪽(요청하는 쪽에 한 번)

```
[파트] 요청 창구 안내
- 개발 요청: 파트 리드에게 보내 주세요. 원문 · 무엇 · 왜(누가 결정) · 언제까지와 이유 · 무엇을 보면 됐다고 할지를 적어 주시면 빠릅니다.
- 기술 문의: 그 프로그램의 리드에게 바로 물어 주세요.
- 긴급(운영 정지·데이터 손실, 시험·계약 일정에 걸린 결함, 안전): 그 프로그램의 리드에게 바로 연락해 주세요.
- 날짜는 담당 리드가 추정한 뒤 근무일 2일 안에 회신드립니다.
```
