# 수첩 2 쓰는 법

관리 수첩 2는 **프로그램 리드 체계**를 돌리는 파트 리드(관리자)용 수첩입니다.
팀원마다 프로그램을 리드 1명 + 서브 1명으로 맡고, 관리자는 방향·지침과 모든 외부 요청 접수를 맡는 구조에 맞췄습니다.

원칙은 셋입니다.

- **상태를 묻지 않습니다.** 물어야 했다면 산출물(진행 지도·결정 로그)의 빈칸입니다. 그 순간을 [물음 메모](#today)로 적습니다.
- **사람을 재지 않습니다.** 숫자는 모두 건 단위입니다. 사람 단위 숫자는 자리 계산(사람별 활성 자리, 상한 검사용) 한 곳뿐입니다. 개인별 진행률·응답 속도·업무량 순위는 없습니다.
- **보내지 않습니다.** 되묻기 문장, 넘길 문장, 주간 보고는 모두 복사해서 직접 붙여 넣습니다.

## 처음 한 번(15분)

1. [설정](#settings)에서 시작일, 사이클(시작 주·길이·정리 주), 쉬는 날을 확인합니다.
2. [설정](#settings)의 사람 표시를 확인합니다. 기본은 A·B·C·D입니다. 이니셜이나 기호만 씁니다. 사람마다 리드 상한을 정합니다.
3. [프로그램·자리](#programs)에서 '프로그램 추가'로 맡은 프로그램을 적고 리드·서브·활성을 고릅니다.
4. [결정 경계](#bounds)의 기본 표를 읽고, 팀과 합의한 것과 다르면 고칩니다.
5. [설정](#settings)에서 일정 파일(.ics)을 받아 업무 캘린더에 넣습니다. 금요 읽기, 월간 리스크 15분, 사이클 시작, 정리 주, 3개월·6개월 점검이 들어갑니다.

## 언제 무엇을 하나

| 때 | 시간 | 하는 것 | 탭 |
|---|---|---|---|
| 매일 아침 | 5분 | 타일 6개와 '지금 손댈 것'을 위에서부터 처리합니다. 열린 막힘의 시계를 봅니다 | [오늘](#today) |
| 요청이 올 때 | 건당 5~10분 | 원문을 적고, 빈칸만 되묻고, 근무일 2일 안에 리드에게 넘깁니다 | [접수함](#intake) |
| 상태가 궁금할 때 | 1분 | 묻지 않고 물음 메모 한 줄 | [오늘](#today) |
| 매주 금요일 | 금요 읽기 시간 안 | 진행 지도의 위험·결정 필요 칸을 옮기고, 초안을 고쳐 복사하고, 이번 주 저장 | [금요일](#friday) |
| 격주 팀장 1:1 | 준비 10분 | 주간 보고에 '2주 초과 약속·거절 결재 요청, 교환 제안 결과'만 더합니다 | [금요일](#friday) |
| 매월 첫 주 | 15분 | 리스크 표 수준을 고르고 '이번 달 점검함'. 시간 일지로 시간 배분 점검 | [수첩](#notebook) |
| 사이클 시작(6주마다) | 2~4시간 | 자리 계산, 프로그램 표 갱신, 지침 네 칸, 사이클 시작 체크 7개 | [프로그램·자리](#programs) |
| 정리 주 | 사이클 끝 1주 | 런북·'혼자 돌리는 데 필요한 것' 갱신, 기술 부채, 다음 사이클 계획 | [프로그램·자리](#programs) |
| 3개월 점검 | 약 1시간 | 서브 혼자 배포가 됐는지, 서브 구현 자리가 돌았는지, 자리 쏠림, 새 자리 적응 | [조심할 것](#guide/watch) |
| 6개월 재검토 | 약 1시간 | 프로그램 리드 체계를 유지할지, 활성 수와 서브 구현 비율, 역할·권한 | [조심할 것](#guide/watch) |

새 회의는 만들지 않습니다. 이미 있는 주간 서면 보고, 격주 팀장 1:1, 월간 리스크 점검에 끼워 넣습니다.

## 탭별로

**[오늘](#today)**: 전달 2일 초과, 접수 대기, 이번 주 흡수 건수, 활성 프로그램, 자리 상한 넘은 사람, 시계 넘긴 막힘을 타일로 봅니다. '지금 손댈 것'은 빈칸 되묻기, 긴급 사후 등록 확인, 자리 경고, 결정 필요, 보류·종료 제안 같은 것을 모아 줍니다. 막힘 패널은 리드가 올린 막힘(근무일 2일)과 헷갈림(근무일 1일)의 시계를 보여 줍니다. 조기 신호 6개 중 둘 이상 켜지면 [조심할 것](#guide/watch)을 봅니다.

**[접수함](#intake)**: 요청을 양식 7칸으로 적습니다. 빈칸은 표에 바로 보이고, '되묻기 문장 복사'는 빈칸만 묻는 문장을 만듭니다. 리드 추정(최소·보통·최대)을 받은 뒤 회신합니다. '리드에게 넘길 문장 복사'는 결정된 것·열린 것·요청자 세 칸입니다. 내가 직접 처리했다면 '흡수 표시'를 합니다. 흡수 건수는 금요일 보고에 건수로만 들어갑니다.

**[프로그램·자리](#programs)**: 사람마다 활성 자리(리드 + 이번 사이클 서브 구현)를 막대로 봅니다. 상한을 넘으면 경고가 뜹니다. 프로그램 표는 Confluence로 복사해 같이 봅니다. 복사한 표에는 사람별 합계가 없습니다. 활성 프로그램마다 지침 네 칸(문제·성공 기준·제약·빼는 것)을 채웁니다.

**[결정 경계](#bounds)**: 누가 최종 결정하는지 적은 1쪽 표, 긴급 기준, 서브 최소 의무, 결정 로그가 있습니다. 결정 로그는 결정자를 이름이 아니라 역할로 적습니다.

**[금요일](#friday)**: 진행 지도의 위험·결정 필요 칸을 옮기면 주간 서면 보고 초안이 만들어집니다. 초안은 칸 안에서 고칠 수 있고, 복사해서 직접 보냅니다. 사내 AI가 켜져 있으면 문장만 다듬을 수 있고, 다듬기 전으로 되돌릴 수 있습니다.

**[수첩](#notebook)**: 관리자만 보는 곳입니다. 물음 메모와 나중에 보낼 것, 시간 일지(첫 2주는 꼭), 리스크 표가 있습니다. 1.0에서 올라왔다면 1.0 금요일 기록이 여기에 읽기 전용으로 보입니다.

**[설정](#settings)**: 시작일·사이클·쉬는 날, 사람 표시와 리드 상한, 자리 상한, 요청자 역할, 긴급 기준, 일정 파일, 내보내기·가져오기, 모두 지우기가 있습니다.

## 1.0에서 올라올 때

1. **먼저 내보내기.** 1.0 화면의 설정 탭에서 '데이터 내보내기(.json)'를 눌러 파일을 받아 둡니다. 볼륨 백업(아래)도 해 두면 더 안전합니다.
2. **컨테이너만 바꿉니다.** 1.0 컨테이너를 지우고, **같은 볼륨**을 붙여 2.0 이미지로 다시 만듭니다. 이미지 주소와 실행 명령은 README에 있습니다. 볼륨은 지우지 않습니다.
3. **그대로 보이는 것.** 물음 메모·나중에 보낼 것은 [수첩](#notebook)과 [오늘](#today)에, 막힘은 [오늘](#today)의 막힘 패널에 그대로 보입니다. 1.0 금요일 기록은 [수첩](#notebook)의 '1.0 기록'에 읽기 전용으로 보입니다. 시작일·쉬는 날 같은 설정도 이어집니다.
4. **새로 채울 것.** 프로그램 표, 접수함, 결정 로그는 비어 있습니다. [처음 한 번](#guide/start)의 3~5번을 합니다. 리스크 표는 처음 열 때 기본 7행으로 채워집니다.
5. **일정 파일을 다시 받습니다.** 2.0 일정은 1.0과 다릅니다. 캘린더에서 지난 `[관리]` 일정을 모두 지운 뒤 새 파일을 가져옵니다.
6. **1.0 내보내기 파일을 2.0에 가져오면** 물음 메모·막힘·금요일·설정만 바뀝니다. 접수함·프로그램 같은 2.0 기록은 그대로 둡니다.

문제가 있으면 1.0 이미지로 컨테이너를 다시 만들고, 1번에서 받은 파일이나 볼륨 백업으로 되살립니다.

## 데이터와 백업

- 기록은 SQLite 파일 하나(`notebook.db`)에만 있습니다. Docker로 쓰면 볼륨 안 `/data/notebook.db`이고 컨테이너를 지워도 볼륨은 남습니다. Windows 실행 파일로 쓰면 `%LOCALAPPDATA%\manager-notebook\notebook.db`이고 실행 파일을 바꿔도 남습니다. 외부로 나가는 연결은 없습니다(사내 AI를 켰을 때 버튼을 누른 순간의 그 주소만).
- **쉬운 백업**: [설정](#settings)의 '데이터 내보내기(.json)'. 되살릴 때는 '가져오기'(두 번 눌러 확인)를 씁니다. 2.0 파일은 모든 기록을 바꿉니다.
- **볼륨 통째로**: 이 이미지에는 셸이 없어서 공개 `busybox` 이미지로 묶습니다. 잠깐 멈추고 하면 파일이 깨지지 않습니다. 컨테이너·볼륨 이름은 실제로 쓰는 이름으로 바꿉니다.

```powershell
cd "$HOME\manager-notebook"
docker stop manager-notebook
docker run --rm -v manager-notebook:/data:ro -v "${PWD}:/backup" busybox:1.37 tar czf /backup/manager-notebook-backup.tgz -C /data .
docker start manager-notebook
```

- 업데이트 전, 그리고 매월 첫 주 리스크 점검 때 한 번씩 받아 두기를 권합니다.
- 내보낸 파일과 백업 파일에도 기록이 그대로 들어 있습니다. 이 PC에만 두고, 공유 폴더·메일·메신저에 올리지 마세요.

## 이 방식의 근거

이 수첩의 장치(상태 대신 산출물 읽기, 리드 전달 2일 하나만 사람이 지키는 약속, 흡수하지 않고 교환 제안하기)는 앞선 시뮬레이션에서 나온 **시뮬레이션 기반 가설**입니다. 실제 조직에서 측정한 값이 아닙니다. 리더십·자율성·감시에 관한 문헌은 **방향만** 빌렸고, 수치는 이 팀에 옮기지 않았습니다. 팀에 '검증된 방식'이라고 소개하지 마세요.
