# 틀 (Confluence·Jira)

팀이 이미 쓰는 Confluence와 Jira에 붙여 쓰는 틀입니다.
새 도구는 없습니다. 새 회의도 없습니다.

## 도입 순서 (한 번에 다 깔지 않습니다)

- **0주(끄기·설정 15분)**: 팀 홈과 팀 약속(헌장) 페이지만 만듭니다. 틀은 아직 걸지 않습니다.
- **1주(10-26 주), 팀 약속(헌장) 합의 뒤**: 1 결정 로그, 3 피치, 4 완료 정의, 6 Jira 규칙. 첫 사이클(11-02) 전에 Confluence에 겁니다.
- **5주 차(11-23 주), 4주 회고 때**: 2 진행 지도. 그 전 금요일에는 결정 로그와 데모만 읽습니다.
- **첫 정리 주(쿨다운), 12-14 \~ 12-18**: 5 사이클 회고.

0주 시작을 2026-10-19(월)로 잡은 날짜입니다. '시작 준비' 문서와 같습니다.

## 팀장만 보기 (팀에 붙이지 않는 부분)

- 틀마다 **▼ 여기부터 복사** 와 **▲ 여기까지** 사이만 Confluence에 붙입니다. 그 밖의 글은 팀장용 메모입니다.
- 이 틀은 **일(항목)** 을 적는 곳입니다. **사람**을 적는 곳이 아닙니다. 어느 틀에도 담당자별·사람별 칸이 없습니다. 넣지 마세요.
- 이 방식은 시뮬레이션 기반 가설입니다. 팀에 '검증된 방식'이라고 소개하지 마세요.

**회사 Confluence가 어느 쪽인지 보는 법**
- 주소가 `○○.atlassian.net` 이면 Cloud입니다.
- 회사 도메인 주소면 대개 Data Center(또는 Server)입니다. (확인 필요)

**붙여 넣는 법**
- Cloud: 편집 화면에 그대로 붙여 넣어 봅니다. 제목·표로 바뀌면 끝입니다. 회색 코드 상자로 붙으면 지우고, 표만 손으로 만드세요. 칸이 몇 개 안 됩니다.
- Data Center: 편집 화면 → 삽입(Insert) → 마크업(Markup) → Markdown 선택 → 붙여 넣기. (확인 필요: 회사 버전에 이 메뉴가 있는지)
- 붙여 넣은 뒤 페이지를 '템플릿'으로 저장해 두면 다음부터 편합니다. (확인 필요: 스페이스 템플릿 권한)

## 1. 결정 로그

▼ 여기부터 복사

언제 쓰나: 팀에 영향이 가는 결정을 내렸을 때. 그 자리에서 한 줄.

'(필수)' 칸만 채우면 됩니다. 나머지는 비워도 됩니다.

| 날짜(필수) | 결정(필수) | 결정자(역할) | 이유(필수) | 바뀌면: 누가, 왜 |
|---|---|---|---|---|
| (예시: 붙여 넣은 뒤 지우세요) 2026-12-18 | 온보딩 문서를 위키 1쪽으로 줄인다 | 팀 합의 | 3쪽은 첫 주에 다 보기 어렵다는 의견(정리 주 회고) | |
| | | | | |

규칙
- 한 결정에 한 줄. 길게 쓰지 않습니다.
- 결정자는 이름 대신 역할로 적습니다(팀장, 상위 리더, 팀 합의).
- 결정이 바뀌면 줄을 지우지 않습니다. 마지막 칸에 '날짜, 누가, 왜'를 적고, 새 결정을 아래 줄에 씁니다.
- 누구나 적을 수 있습니다. 팀장이 회의 중에 적어도 됩니다.

▲ 여기까지

## 2. 진행 지도

▼ 여기부터 복사

언제 쓰나: 사이클 시작 때 항목을 적습니다. 그다음엔 **상태가 바뀐 날에만** 한 단어 고칩니다. 매일 고치지 않습니다.

사이클: ___ (예: 2026-11-02 \~ 12-11, 6주) · 정리 주: ___ (예: 12-14 \~ 12-18)

| 항목(필수) | Jira 에픽 | 상태(필수) | 위험 | 결정 필요 |
|---|---|---|---|---|
| (예시: 붙여 넣은 뒤 지우세요) 온보딩 문서 개편 | (에픽 링크) | 실행 중 | 사내 위키 권한 승인이 늦음 | 위키 권한 요청을 팀장이 대신 올릴지 |
| | | | | |

상태는 셋 중 하나만 씁니다.
- **파악 중**: 무엇을 할지, 어디가 어려운지 아직 알아보는 중.
- **실행 중**: 할 일이 보이고 만드는 중.
- **마무리**: 남은 건 확인·정리뿐.

규칙
- 상태를 고치는 곳은 **이 표 한 곳**입니다. 그 일을 움직이는 사람 누구나, 바뀐 날 한 단어만 고칩니다. Jira 에픽 상태와 맞추지 않아도 됩니다.
- 이 칸이 비어 있거나 늦게 고쳐져도 팀장은 묻지 않습니다.
- 사람별 칸, 담당자 칸, 진척 % 칸을 만들지 않습니다.
- 위험과 결정 필요는 있을 때만 씁니다. 금요일 팀 요약은 이 두 칸에서 가져옵니다.
- 진행 지도의 한 줄은 Jira 에픽 하나입니다. 에픽 안의 작은 일은 Jira에만 둡니다.

▲ 여기까지

### 팀장만 보기: 진행 지도 쓰는 법과 Jira 연결

- 처음 거는 날은 5주 차(11-23 주)입니다. 사이클 중간이니 지금 하고 있는 항목만 적고 시작합니다.
- 금요일에 이 표를 읽습니다. 표를 보고 개인에게 상태를 묻지 않습니다. 궁금한 게 생기면 이 도구의 '적기' 탭에 물음 메모로 적습니다.
- 'Jira 에픽' 칸에는 에픽 링크만 붙입니다.
- 원하면 표 위에 Jira 목록을 자동으로 띄울 수 있습니다(선택).
  - Cloud: 편집 화면에서 `/jira` 입력 → 'Jira work items' 선택 → JQL 입력.
  - JQL 예: `project = ABC AND issuetype = Epic AND statusCategory != Done`
  - `ABC` 자리에는 팀 프로젝트 키를 넣습니다. 작업 번호 앞 글자입니다(예: ABC-12의 ABC).
  - Jira 화면이 한국어면 Epic이 '에픽'일 수 있습니다. (확인 필요)
  - 목록이 뜬 뒤 열 아이콘(또는 Display options)에서 열을 고릅니다. 키, 요약, 상태만 남기고 **담당자(Assignee) 열은 끕니다.**
  - Data Center는 'Jira 이슈' 매크로 이름과 열 고르는 메뉴가 다를 수 있습니다. (확인 필요)
- Jira 보드의 스윔레인은 '없음' 또는 '에픽'으로 둡니다. '담당자'로 나누지 않습니다. (확인 필요: 보드 설정에서 스윔레인 메뉴 위치)

## 3. 피치 템플릿

▼ 여기부터 복사

언제 쓰나: 다음 사이클에 하고 싶은 일이 있을 때. 누구나 씁니다. 정리 주에 모아 봅니다. 처음은 1주(10-26 주)에 사이클 1에 넣을 일을 고를 때입니다.

작성자: (선택. 비워도 됩니다)

| 칸 | 내용 |
|---|---|
| 문제(필수) | 무엇이 불편하거나 막혀 있나요? 지금 어떻게 버티고 있나요? |
| 시간 예산(필수) | 이 문제에 쓸 만한 최대 시간. 예: 2주, 6주 한 사이클. 넘으면 범위를 줄입니다. |
| 해법 스케치(필수) | 대략 어떻게 풀지. 그림이나 목록 몇 줄이면 충분합니다. 완성도는 필요 없습니다. |
| 빼는 것 | 이번엔 일부러 안 하는 것. |
| 위험 | 시간 예산을 넘길 수 있는 곳, 모르는 것. |

규칙
- 직급·연차와 상관없이 누구나 올립니다.
- 피치가 뽑히지 않아도 기록은 남습니다. 다음 정리 주에 다시 올릴 수 있습니다.
- 뽑는 이유(베팅 근거)는 결정 로그에 한 줄로 적습니다.

▲ 여기까지

## 4. 완료 정의(DoD)

▼ 여기부터 복사

언제 쓰나: 일을 본격적으로 만들기 시작할 때(진행 지도의 '실행 중') 한 번. 5분 안쪽. '(필수)' 두 칸만 채우면 됩니다.

| 칸 | 내용 |
|---|---|
| 이게 되면 끝(필수) | 1\~3줄 |
| 이 정도면 충분(필수) | 더 다듬고 싶어도 여기서 멈추는 선 |
| 이번엔 안 함 | 다음 사이클로 미루는 것 |
| 확인 방법 | 무엇을 보면 끝났다고 알 수 있나 |

'이 정도면 충분' 예시 (온보딩 문서 개편. 붙여 넣은 뒤 지우세요)

| 칸 | 내용 |
|---|---|
| 이게 되면 끝 | 새로 온 사람이 위키 1쪽만 보고 첫 주 할 일 5개를 안다 |
| 이 정도면 충분 | 표와 링크로 된 1쪽. 그림·영상은 없어도 된다 |
| 이번엔 안 함 | 직무별 상세 가이드, 영어판 |
| 확인 방법 | 금요일 데모에서 화면으로 보여 준다 |

규칙
- DoD는 일의 끝을 정하는 것입니다. 사람을 평가하는 기준으로 쓰지 않습니다.
- 사이클 중에 '충분'의 선을 낮추는 것은 실패가 아니라 결정입니다. 결정 로그에 적습니다.

▲ 여기까지

## 5. 사이클 회고

▼ 여기부터 복사

언제 쓰나: 정리 주 금요일 15:30 데모 자리를 회고 30분으로 씁니다. 첫 회고는 12-18(금)입니다. 새 회의를 더 만들지 않습니다.

순서
1. 회고 2일 전: 익명 서면 질문 4개를 보냅니다. 첫 회고 질문은 12-16(수)에 보냅니다.
2. 회고 전날: 팀장이 답을 한 페이지에 모읍니다. 사람 이름이나 누구인지 알 수 있는 표현만 '어떤 일'로 바꾸고, 나머지 내용은 고치지 않습니다. 누가 썼는지 추측하지 않습니다.
3. 회고 30분: 그 페이지를 같이 보고 '다음 사이클에 바꿀 것 1\~2개'만 정합니다. 결정 로그에 적습니다.

질문 4개
1. 이번 사이클에 일을 늦추거나 막은 것은 무엇이었나요? (사람 말고 일·절차·도구·요청으로)
2. 잘 된 일 하나와, 무엇이 그걸 가능하게 했나요?
3. 팀 약속(조용한 시간, 48시간 회신, 동시 착수 2개, 처벌 없는 이월) 중 지키기 어려웠던 것과, 어렵게 만든 일·절차는? 팀장이 먼저 바꿀 것은? (다른 사람이 아니라 상황으로)
4. 다음 사이클에 하나만 빼거나 바꾼다면?

규칙
- 회고 결과로 개인을 평가하지 않습니다. 개인별 정리도 만들지 않습니다.

▲ 여기까지

### 팀장만 보기: 회고 준비

- 이 30분은 실행 가이드 사이클 루틴의 정리 주 회고입니다. 관리 시간 예산에 이미 들어 있습니다. 자리는 정리 주 금요일 15:30 데모 자리입니다.
- 익명 양식은 회사 설문 도구나 응답자 정보 수집을 끈 양식을 씁니다. Confluence 댓글은 이름이 남아서 익명이 아닙니다. 헌장 4절의 익명 폼을 같이 써도 됩니다. (확인 필요: 회사에서 쓸 수 있는 익명 양식 도구)
- 8명 팀이면 말투만으로도 누가 썼는지 드러날 수 있습니다. 걱정되면 원문을 붙이지 말고 **같은 내용끼리 묶어 요약**해 붙여도 됩니다. 요약할 때도 내용을 빼거나 누그러뜨리지 않습니다.

## 6. Jira 사용 규칙 한 장

▼ 여기부터 복사

언제 쓰나: 첫 사이클(11-02) 전에 팀과 한 번 읽고, Confluence에 걸어 둡니다. 팀 약속(헌장) 2절과 같은 내용입니다.

### 막혔을 때, 헷갈릴 때

- **올리는 곳은 Synology Chat `#막힘-헷갈림` 한 곳**입니다.
  - 채널 이름은 가칭입니다. 10-26 팀 약속에서 확정합니다. 한글 이름이 안 되면 `#help-blocked`를 씁니다.
  - 막힘: `[막힘] 무엇이 멈췄나 한 줄 + Jira 링크`
  - 헷갈림: `[헷갈림] 무엇이 헷갈리나 한 줄`
- 채널에 쓰기 곤란하면 팀장에게 1:1 메시지로 보내도 됩니다. 약속은 같습니다.
- 헷갈림에는 Jira 플래그를 걸지 않습니다. 플래그를 건 카드는 팀 보드 전체에 노랗게 보이기 때문입니다.
- 막힘에 Jira 플래그를 거는 것은 **선택**입니다. 보드에서 카드를 노랗게 보이게 하고 싶을 때만 겁니다. 채널 글 하나면 충분합니다.

팀장은 이렇게 답합니다
- **막힘: 48시간 안에** 그 글의 스레드에 답합니다. `덜었다: (무엇을)` 또는 `못 덜었다: (이유) / 대신 조정한 것: (마감, 범위, 순서 등)`.
- **헷갈림: 24시간 안에** 15분을 잡아 첫 조각을 같이 쪼갭니다.
- 48시간·24시간은 **근무일 기준**입니다.
  - 막힘은 근무일 2일, 헷갈림은 근무일 1일입니다.
  - 토·일·공휴일은 세지 않습니다.
  - 19시 이후나 쉬는 날에 들어온 글은 다음 근무일 09시부터, 근무일 08시 이전에 들어온 글은 그날 09시부터 셉니다.
  - 예: 금 17시 막힘 → 화 17시까지. 목 11시 헷갈림 → 금 11시까지.
- 19\~08시와 주말에는 답하지 않습니다. 올리는 사람도 이 시간에 답을 기다리지 않아도 됩니다.
- 팀장 권한 밖의 결정이 필요하면 `시계 멈춤: (누구 결정 필요) / 다시 알릴 날: (날짜)`로 답합니다.
  - 팀장보다 위나 다른 팀의 결정이 필요할 때만 멈춥니다.
  - 멈춘다는 사실은 기한 안에 알립니다.
  - 멈춘 동안 지난 근무일만큼 기한이 뒤로 갑니다.
- 팀 약속에서 당번을 정했다면, 팀장이 없을 때 당번이 대신 받습니다. 팀장 부재 일정은 미리 채널에 알립니다.
- 당번이 정해지기 전에는, 부재 중에 온 글을 복귀일 09시부터 셉니다. 부재 공지에 복귀일을 적습니다.
- 월요일 막힘 풀기(10:00\~10:30, 11-02부터)에서는 `#막힘-헷갈림`에 남은 막힘 글만 봅니다(Jira 플래그가 있으면 함께).
  - 선택 참석입니다. 막힘을 올린 사람과 관련자만 모입니다.
  - 09:30까지 남은 막힘이 없으면 취소합니다.
  - 11-23(월)은 취소하지 않습니다. 이날은 팀 전체 4주 회고 30분으로 씁니다.

### 동시 착수 2개

- 한 사람이 동시에 '진행 중'인 항목은 2개까지. 각자 스스로 지킵니다. 팀장이 사람별로 세지 않습니다.
- 셋째 일이 오면 하나를 끝내거나 내려놓고 시작합니다.
- 내려놓은 항목은 Jira에서 상태를 '할 일'로 되돌리면 됩니다. 따로 알릴 필요 없습니다.
- 넘칠 것 같으면 '막힘'으로 올려 주세요.
- 내려놓은 일이 팀 전체 일정에 영향을 주면, 진행 지도의 위험 칸에 한 줄 적습니다.

### 못 끝낸 일은 그대로 이월

- 사이클이 끝날 때 못 끝낸 항목은 **그대로 다음 사이클로** 옮깁니다. 처벌도, 사유서도 없습니다.
- '지연', '이월' 같은 라벨이나 빨간색을 붙이지 않습니다.
- 기한(Due date) 칸에는 **팀 밖과 약속한 마감만** 적습니다. 팀 안의 중간 마감은 적지 않습니다.
- 스프린트 보고서의 미완료 목록을 사람별로 세지 않습니다. 이월 수로 사람을 보지 않습니다.

### 이월할 때 한 줄: 범위 줄이기 결정

- 이월하는 항목마다 코멘트 한 줄만 남깁니다.
- 형식: `범위 줄이기 결정: 다음 사이클엔 ___까지만. ___는 뺀다.`
- 예: `범위 줄이기 결정: 다음 사이클엔 1쪽 초안까지만. 영어판은 뺀다.`
- 누가 써도 됩니다. 사이클 마지막 날 팀장이 같이 정해도 됩니다.
- 큰 결정이면 결정 로그에도 한 줄.

### Jira에서 쓰지 않는 것

- 사람별 필터·워크로드 뷰·개인 대시보드
- 작업 시간 기록(타임트래킹), 개인 번다운
- 스토리 포인트를 평가에 쓰기
- 담당자별 스윔레인
- 매일 상태 업데이트 요구

### 팀장만 보기: Jira 설정 메모

**막힘 플래그(선택)를 거는 법**
- Cloud: **보드나 백로그의 카드에서** 더보기(•••, 또는 우클릭) → 플래그 추가(Add flag) → 뜨는 창에 코멘트 한 줄.
- 작업 항목 상세 화면에서 걸면 코멘트 창 없이 플래그만 걸릴 수 있습니다. 그때는 코멘트를 따로 한 줄 답니다.
- Data Center: 보드에서 카드 우클릭 → Add flag and comment. (확인 필요)
- 한국어 화면의 메뉴 이름과, 플래그를 걸면 누구에게 알림이 가는지는 확인 필요. 그래서 채널 글이 기본입니다.
- 플래그 걸린 항목은 JQL `Flagged = Impediment`로 모아 볼 수 있습니다. 월요일 막힘 풀기 때만 엽니다. 매일 열지 않습니다.

**48시간 시계**
- 48시간 약속을 지키는 기본 도구는 이 도구의 '막힘' 탭입니다. Synology Chat의 Remind me는 덧붙여 쓰는 선택 알림입니다.
- 이 도구의 '막힘' 탭 시계도 같은 기준(근무일 이틀, 주말·공휴일 제외)으로 셉니다. 다르게 셀 때는 이 틀을 기준으로 맞춥니다.
- 팀장 부재 기간은 이 도구 설정 탭의 '쉬는 날'에 넣습니다.

**동시 착수: 칼럼 상한은 걸지 않습니다**
- Jira 기본 기능으로는 사람별 상한을 걸 수 없습니다(칼럼 단위만 됨). 사람별 상한 앱이나 사람별 필터도 깔지 않습니다.
- '진행 중' 칼럼에 팀 전체 상한을 거는 것은 **권하지 않습니다.** 넘으면 칼럼이 빨개지고, 빨간 칼럼을 보면 누가 넘었는지 카드를 훑게 되기 때문입니다.
- '끄기·설정' 문서도 같은 기준입니다(기본은 걸지 않음, 팀이 원하면 4주 회고에서 켬).

**이월하는 법**
- 스크럼 보드: 스프린트 완료(Complete sprint) 창에서 남은 항목을 다음 스프린트로 옮깁니다. 팀장이 한 번에 합니다.
- 칸반 보드: 옮길 것이 없습니다. 진행 지도의 사이클 이름만 바꿉니다.
- 지난 기한이 카드에 빨갛게 보이는지는 회사 Jira에서 확인 필요.
- 범위 줄이기 결정용 전용 입력 칸(커스텀 필드)을 만들려면 Jira 관리자 권한이 필요할 수 있습니다. 코멘트로 충분하니 처음엔 만들지 않습니다. (확인 필요)

**사이클 길이**
- 기본은 6주 + 정리 주 1주입니다. 팀 일이 작으면 4주 + 1주도 됩니다.
- 스크럼 보드: 스프린트 시작(Start sprint) 창 → 기간(Duration): 사용자 지정(Custom) → 종료일을 6주 뒤 금요일로 고릅니다. 첫 사이클은 12-11(금). 정리 주에는 스프린트를 열지 않습니다.
- 한국어 화면의 메뉴 이름과 Data Center에서 되는지는 확인 필요.
- 사용자 지정이 막혀 있으면 2주 스프린트로 쪼개지 마세요. 2주마다 완료 창과 미완료 목록이 생깁니다. 대신 **칸반 보드**로 쓰고, 진행 지도에 사이클 이름만 둡니다. 진행 지도가 생기기 전(5주 차 전)에는 사이클 이름을 보드 이름이나 결정 로그에 적습니다.
